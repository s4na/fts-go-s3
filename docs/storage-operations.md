# S3 運用上の前提

## IAM 権限

Amazon S3 は現時点では CI で検証していません。S3 で索引の作成・検索・同期・回収を行う場合、操作に応じて索引のプレフィックスに対する `s3:GetObject`、`s3:PutObject`、`s3:DeleteObject` と、バケットに対する `s3:ListBucket` が必要です。同期元の文書には `s3:GetObject` と、同期元の一覧取得に必要な `s3:ListBucket` が必要です。アクセス範囲はそれぞれのプレフィックスに絞ってください。読み取りだけなら、その処理で不要な書き込みや削除の権限は不要です。

特に `s3:ListBucket` がない場合、存在しないオブジェクトの取得に Amazon S3 が 404 ではなく 403 を返すことがあります。この場合、まだ存在しない manifest を新規作成する処理は、権限エラーと存在しない状態を区別できずに失敗します。403 を不在とみなして無条件に作成しないでください。

## 同期元と索引のプレフィックス

S3 の一覧の `prefix` は文字列の先頭一致であり、`/` をディレクトリ区切りとして扱いません。たとえば `doc` を指定すると `docs-index/...` も一覧に含まれます。そのため、`Sync` は互いに文字列として前方一致する同期元・索引のプレフィックスを拒否します。分けたい場合は `doc/` と `docs-index/` のように末尾の `/` まで指定してください。この判定は、異なる `Store` を渡した場合にも安全側に適用されます。

## 競合と再試行

`Reclaim` は安全な削除の境界を設けるため、マニフェストを条件付きで更新します。同期や追加と同時に動かすと `ErrConflict` を返す場合があります。CLI は競合を最大 3 回試しますが、競合が続く環境での成功は保証しません。その場合は時間を空けて再実行してください。`RetryConflict` を直接使う場合も、再試行ごとに最新の状態を読み直してください。
