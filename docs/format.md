# 保存形式 v1 / v2

形式バージョンはライブラリのリリース番号とは独立しています。マニフェストとセグメントの未知バージョンは拒否します。すべてのオブジェクトは設定されたインデックスプレフィックスの下に置きます。

`manifest` はバージョン 1 の JSON で、`version`、公開ごとに変わるランダムな `generation`、古い順の `segments` 配列を持ちます。各参照はセグメントキー・バイト長・文書数だけを持ち、文書キーの一覧は含みません。公開時は前の ETag を条件に PUT し、存在しない場合は `If-None-Match: *` を使います。セグメントは公開前に固有名で書く不変オブジェクトです。途中失敗で残ったオブジェクトは未参照として回収できます。

セグメントはエントリー群、64 件ごとのソート済み辞書ブロック、疎なブロック目次と文書キーの Bloom フィルタ（SHA-256 チェックサム付き）、32 バイトのフッターを連結した 1 オブジェクトです。辞書はエントリー名と offset / length を保持します。`a` は文書キーのソート済み JSON 配列、`k` + キーは文書の削除状態・term・同期元 ETag、`t` + term はその term を持つ文書のポスティングです。term は `u` + 1 文字または `b` + 2 文字です。削除の印はそのキーの文書レコードとして新しいセグメントに保持します。

**v1** のポスティングは文書キーのソート済み JSON 配列です。**v2** は `a` の先頭から 1 を起点として連番を割り振った文書 ID を、昇順の差分にして符号なし varint（LEB128）で連結します。先頭の差分は最初の文書 ID、以後は直前の ID との差で、すべて正です。v2 の検索用には同じキー表を 256 件単位の `d` + ブロック番号（8 桁の 16 進数）に分け、該当 ID のブロックだけ読みます。キャッシュはセグメントごとにシリアライズ時のサイズ合計 64 KiB 以下です。`a` は従来どおり、すべての文書の列挙に使います。v1 と v2 は同じマニフェストに混在でき、読み取りとコンパクションで対応します。

新しいセグメントは **v2 で書き**、既存の v1 と新しい v2 の両方を読みます。v2 を書いた索引は、v1 のみ対応する古いライブラリでは読めません。複数のプロセスで同じ索引を使っている場合は、書き込みを停止して全プロセスを更新してから再開してください。v2 のデータを書いた後に古いバージョンへ戻す場合は、古いバージョンが読める別の索引を用意する必要があります。

セグメントの形式番号はファイルを読む方法を示す番号であり、Go モジュールのリリース番号ではありません。この変更は Go モジュールを `v2.0.0` にしたり、import パスへ `/v2` を追加したりするものではありません。

フッターは先頭 8 バイトが `ZENBUN01`、次の 4 バイトがビッグエンディアンのバージョン、次の 4 バイトが予約領域、残りが目次の offset と length（各 8 バイト、ビッグエンディアン）です。読み取り側は範囲と文書 ID を検証してから結果を返します。検索は目次、必要な辞書ブロックとポスティングを読み、後続セグメントの Bloom フィルタとキー辞書で上書き・削除を判定します。Bloom フィルタは存在しないキーの読み取りを省くだけで、存在の確認はキー辞書で行います。コンパクションは隣接セグメントを順序を保って統合し、最古のセグメントを含む統合では、古い値を抑止する必要がなくなった削除の印を除去します。

索引の term は書き込み時の NFKC 正規化と小文字化に依存します。v2 の導入自体は正規化処理を変更せず、v1 の term をそのまま使用します。正規化ライブラリの更新によって結果が変わる場合、既存の索引を新しい正規化で再構築する必要があります。単にセグメントをコンパクションしても元の本文から再構築されません。

回収はまずセグメントを一覧し、次にマニフェストを条件付き更新して書き手との境界を作ります。一覧に現れた未参照セグメントに `retired/<id>` の印を付けます。一覧中に別の公開が成功した場合は条件付き更新が失敗し、印付けを行いません。印の作成時刻から猶予が経過した次回以降に削除します。セグメント名の再利用は禁止します。読み取り時間・時計差・一覧遅延に関する前提は README のとおりです。
