# 保存形式 v1

形式バージョンはライブラリのリリース番号とは独立しています。マニフェストとセグメントの未知バージョンは拒否します。すべてのオブジェクトは設定されたインデックスプレフィックスの下に置きます。

`manifest` は JSON で、`version`、公開ごとに変わるランダムな `generation`、古い順の `segments` 配列を持ちます。各参照はセグメントキー・バイト長・文書数だけを持ち、文書キーの一覧は含みません。公開時は前の ETag を条件に PUT し、存在しない場合は `If-None-Match: *` を使います。セグメントは公開前に固有名で書く不変オブジェクトです。途中失敗で残ったオブジェクトは未参照として回収できます。

セグメントは、JSON エントリー群、64 件ごとのソート済み辞書ブロック、疎なブロック目次と文書キーの Bloom フィルタ（SHA-256 チェックサム付き）、32 バイトのフッターを連結した 1 オブジェクトです。辞書はエントリー名と offset / length を保持します。`a` は文書キー一覧、`k` + キーは文書の削除状態・term・同期元 ETag、`t` + term はその term を持つ文書キーのソート済み一覧です。term は `u` + 1 文字または `b` + 2 文字です。削除の印はそのキーの文書レコードとして新しいセグメントに保持します。

フッターは先頭 8 バイトが `ZENBUN01`、次の 4 バイトがビッグエンディアンのバージョン、次の 4 バイトが予約領域、残りが目次の offset と length（各 8 バイト、ビッグエンディアン）です。読み取り側は範囲を検証してから Range GET します。検索は目次、必要な辞書ブロックとポスティングを読み、後続セグメントの Bloom フィルタとキー辞書で上書き・削除を判定します。Bloom フィルタは存在しないキーの読み取りを省くだけで、存在の確認はキー辞書で行います。コンパクションは隣接セグメントを順序を保って統合し、最古のセグメントを含む統合では、古い値を抑止する必要がなくなった削除の印を除去します。

回収はマニフェストを条件付き更新して書き手との境界を作り、その時点の未参照で、境界より猶予時間以上前に作成されたセグメントに `retired/<id>` の印を付けます。これにより境界以降の書き手が作成したオブジェクトを誤って印付けしません。印の作成時刻から猶予が経過した次回以降に削除します。セグメント名の再利用は禁止します。読み取り時間・時計差・一覧遅延に関する前提は README のとおりです。
