# 保存形式

形式バージョンはライブラリのリリース番号とは独立しています。マニフェストとセグメントの未知バージョンは拒否します。すべてのオブジェクトは設定されたインデックスプレフィックスの下に置きます。

`manifest` はバージョン 1 の JSON で、`version`、公開ごとに変わるランダムな `generation`、古い順の `segments` 配列を持ちます。各参照はセグメントキー・バイト長・文書数だけを持ち、文書キーの一覧は含みません。公開時は前の ETag を条件に PUT し、存在しない場合は `If-None-Match: *` を使います。セグメントは公開前に固有名で書く不変オブジェクトです。途中失敗で残ったオブジェクトは未参照として回収できます。

セグメントはエントリー群、64 件ごとのソート済み辞書ブロック（エントリー群の途中に置く）、疎なブロック目次と文書キーの Bloom フィルタ（SHA-256 チェックサム付き）、32 バイトのフッターを連結した 1 オブジェクトです。辞書はエントリー名と offset / length を保持します。`t` + term はその term を持つ文書のポスティング、`d` + ブロック番号は文書表です。term は `u` + 1 文字または `b` + 2 文字です。削除の印はそのキーの文書レコードとして新しいセグメントに保持します。

ポスティングは、文書表での位置（1 起点）を文書 ID として、昇順の差分にした符号なし varint（LEB128）で連結します。先頭の差分は最初の文書 ID、以後は直前の ID との差で、すべて正です。文書表は、キー順に並べた文書 256 件ごとの JSON 配列で、各要素は `{"key", "deleted", "etag"}`（`deleted` と `etag` は値があるときだけ）です。目次の `doc_first` は各文書表ブロックの先頭キーの配列で、キーの存在確認はこれを二分探索して 1 ブロックだけ読みます。term は文書ごとには保存しません。キャッシュはセグメントごとにシリアライズ時のサイズ合計 64 KiB 以下です。

セグメントは 1 回の走査で書けるよう、文書表 → ポスティングの順にエントリーを書き、64 件たまるごとにその辞書ブロックを直後に書きます。そのため文書表の連続したブロックの間に辞書ブロックが挟まることがあり、まとめ読みはその隙間も含めて読みます。読み取り側は、フッターのバージョンが 3 で目次の `doc_block_size` が 256 であること、文書数が 1 以上であること、`doc_first` の長さが文書数 / 256 の切り上げと一致し狭義昇順であること、各ブロックの件数・キーの昇順・先頭キーが `doc_first` と一致することを検証します。

コンパクションはセグメントの term をポスティングから復元します（現状はセグメント全体を 1 回読む。ポスティングを直接統合する方式は #66）。Sync は文書表だけを読み、term は読みません。

現在の保存形式はバージョン 3 だけです。以前のバージョン（v1 / v2）で書かれた索引は読めません。該当する索引は、元の文書から再構築してください。

フッターは先頭 8 バイトが `ZENBUN01`、次の 4 バイトがビッグエンディアンのバージョン、次の 4 バイトが予約領域、残りが目次の offset と length（各 8 バイト、ビッグエンディアン）です。読み取り側は範囲と文書 ID を検証してから結果を返します。検索は目次、必要な辞書ブロックとポスティングを読み、後続セグメントの Bloom フィルタと、文書表で上書き・削除を判定します。Bloom フィルタは存在しないキーの読み取りを省くだけで、存在の確認は文書表で行います。コンパクションは隣接セグメントを順序を保って統合し、最古のセグメントを含む統合では、古い値を抑止する必要がなくなった削除の印を除去します。

索引の term は書き込み時の NFKC 正規化と小文字化に依存します。正規化ライブラリの更新によって結果が変わる場合、既存の索引を新しい正規化で再構築する必要があります。単にセグメントをコンパクションしても元の本文から再構築されません。

回収はまずセグメントを一覧し、次にマニフェストを条件付き更新して書き手との境界を作ります。一覧に現れた未参照セグメントに `retired/<id>` の印を付けます。一覧中に別の公開が成功した場合は条件付き更新が失敗し、印付けを行いません。印の作成時刻から猶予が経過した次回以降に削除します。セグメント名の再利用は禁止します。読み取り時間・時計差・一覧遅延に関する前提は README のとおりです。

S3 の権限・同期元プレフィックス・競合時の再試行は [S3 運用上の前提](storage-operations.md)を参照してください。
