# fts-go-s3

S3 互換ストレージ上の全文検索の成立性を GitHub Actions で検証するプロトタイプです。計画は [#3](https://github.com/s4na/fts-go-s3/issues/3) を参照してください。

最初の検証では、標準ライブラリによる SigV4 クライアントを使い、VersityGW と SeaweedFS で読み書き、Range、一覧、条件付き書き込みを調べます。結果は Actions のジョブサマリーと JSON artifact に記録します。転送量は HTTP ボディの実測値で、ヘッダーやプロトコルのオーバーヘッドは含みません。条件付き書き込みの未対応は実験結果として記録し、通常操作の失敗はテストを失敗させます。

後続の PR でデータセット、オラクル、検索・差分更新、遅延注入と比較実験を追加します。ローカルでは実行せず、検証は GitHub Actions で行います。

データセットとオラクルの Actions では、固定リビジョンの日本語 Wikipedia と青空文庫の本文を取得し、S（1,000件）・M（10,000件）の記事と長文2作品からクエリを生成します。L（100,000件）は手動・週次で実行します。文書とクエリは NFKC 正規化と小文字化を行い、タイトルと本文を対象とした部分文字列検索の全走査を正解とします。元文書はリポジトリや artifact に含めません。Wikipedia は CC BY-SA、青空文庫は著作権保護期間が終了した作品です。

検索プロトタイプは文書のタイトルと本文を文字単位・bi-gram に分割し、term のハッシュで S3 オブジェクトに分割した転置インデックスを作ります。ポスティングは文書IDの差分を varint に符号化し、検索では必要なシャードだけを読み取ります。各クエリをオラクルと突き合わせ、取りこぼしがあれば CI を失敗させ、誤候補・リクエスト・ボディ転送量・時間を記録します。現在の全件構築は空のプレフィックス向けで、更新と並行制御は後続の検証で追加します。

差分更新は新しい不変セグメントを書いてから、古い版の無効化と新しい版をマニフェストの条件付き PUT で公開します。追加・置換・削除と複数文書のバッチに対応し、競合では更新を公開せずエラーを返します。競合で使われなかったセグメントや古いセグメントの回収は後続の検証対象です。

コンパクションは有効なポスティングを新しい不変セグメントに統合し、無効な文書版をマニフェストから取り除いて条件付き PUT で公開します。古いマニフェストを保持する読み手のため、旧セグメントの回収は読み取りリースと猶予期間の後に行います。

追加の Actions は VersityGW / SeaweedFS、S/M、256 シャード・0/20/50ms と 16 シャード・0ms を比較します。Toxiproxy の upstream ストリームに遅延を与えるため、遅延は TCP のデータ単位に適用され、厳密に HTTP リクエスト1件あたり固定ではありません。構築は直接ストレージに行い、検索のみプロキシを通します。レイテンシは参考値として扱い、リクエスト数と転送量を主に比較します。

反復更新の Actions は Wikipedia 記事を使い、PR では少数の個別更新と100件バッチ、手動・週次では1,000回の個別更新と100件バッチ10回を実施します。途中とコンパクション前後の検索を全文走査と照合し、セグメント数、GET、書き込み量の推移を記録します。

比較用に、全シャードを1オブジェクトにまとめてマニフェストの目次から必要な範囲を Range GET する方式も用意しています。検索対象とクエリ、ポスティングの符号化を揃えて、独立シャード方式の構築 PUT・検索 GET・転送量と比較します。

Bloom フィルタの比較では、セグメント内に存在しない term をマニフェストのフィルタで判定し、不要な GET を省きます。フィルタは誤って候補を落とさないことをオラクルと照合し、フィルタ自体によるマニフェストの転送量増加も計測します。

ポスティング符号化の独立した比較モジュールでは、実記事とクエリから得た term ごとの文書 ID 列を、差分 varint と Roaring Bitmap で符号化します。復号の一致を確認し、符号化サイズ・時間、依存グラフとバイナリサイズを Actions で記録します。比較用依存は本体のモジュールには追加しません。

S3 クライアントの比較では、独立モジュールの AWS SDK for Go v2 と自作クライアントを両ストレージで同じ操作に通し、互換性、リクエスト・ボディ転送量、依存グラフとバイナリサイズ、自作コード行数を記録します。SDK 比較用の依存は本体には含みません。

bleve の参考比較では、同じ文書とクエリを既定の MatchQuery と既定アナライザで検索し、NFKC 小文字化した部分文字列検索のオラクルとの差を種類別に記録します。検索意味論は異なるため、取りこぼしや誤候補はその違いを含む参考値です。

旧セグメントの回収実験では、検索・圧縮に最大1分の読み取りリースを設け、期限切れのキャッシュを拒否します。圧縮の公開が遅れても保護期間を確保できるよう、退役時刻を保守的に未来へ置き、さらにリースと時計差10秒以上の猶予を経過してから明示的に回収します。時計差は最大10秒で、ストレージは要求を受けてから1分以内に処理を終えるという前提です。未公開の孤立セグメントは回収しません。
